三、开始二次开发
推荐安装 Node.js 24 LTS，本轮实测版本为 24.22.1。npm 随 Node.js 一起安装。
在项目根目录打开终端并依次执行：

  npm ci
  npm run dev

首次 npm ci 需要网络，依照随包的 package-lock.json 安装完整开发依赖。
成功启动后访问终端打印的地址，默认 http://127.0.0.1:5173。
Windows PowerShell 若提示不允许运行 npm.ps1，请将命令中的 npm 改成 npm.cmd；无需修改执行策略。
修改 src/ 后开发服务器会自动刷新。Ctrl+C 停止服务器。
项目没有后端、数据库、账号系统或 API 密钥；不需要原开发机的 D 盘附件才能运行或构建。
127.0.0.1 只指向当前电脑；本包没有公网部署或开机自动运行设置。

四、构建与生成新版离线试玩
在项目根目录依次执行：

  npm run build
  npm run preview -- --port 4273 --strictPort

浏览器访问 http://127.0.0.1:4273。这个服务只读 dist/，改完源码后必须重新 build。
端口已占用时不会接管或停止其他服务；可以改成另一个空闲端口。
另开终端，在完成 build 后生成离线 HTML：

  node scripts/build-single-file.mjs

输出到 release/库边秘技-试玩版.html，替换旧试玩文件。
仅运行游戏和构建不需要 Python、FFmpeg 或 Blender。
只有重裁剪击球音效、转换模型时才需要相应工具，流程见 scripts/ 和资产清单。
部分早期诊断/导入脚本留有原作者机器地址；这些不是启动或生产构建的依赖，复用前应调整路径。

七、完整性检查
压缩包制作后按每个文件逐一比对工程原件 SHA256，并验证 ZIP CRC 和旧源码包文件清单，确保没有漏掉原 876 个文件。
包内校验清单使用“64 位 SHA256、两个空格、相对路径”的格式。
Windows PowerShell 可在解压后的项目根目录执行：

  $bad = @()
  Get-Content -LiteralPath '.\文件校验-SHA256.txt' -Encoding UTF8 | ForEach-Object {
    $expected, $relative = $_ -split '  ', 2
    if (-not (Test-Path -LiteralPath $relative -PathType Leaf)) {
      $bad += "缺失：$relative"
    } elseif ((Get-FileHash -LiteralPath $relative -Algorithm SHA256).Hash.ToLowerInvariant() -ne $expected) {
      $bad += "不一致：$relative"
    }
  }
  if ($bad.Count) { $bad; throw '校验失败' } else { '全部文件校验通过' }

源代码经正常修改后，其哈希与原交接清单不同属于预期；校验主要用于刚收到文件时排除损坏和漏传。
